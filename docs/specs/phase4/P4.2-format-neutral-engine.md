# P4.2 Format-neutral engine and API

Plan: [PHASE4.md](../../PHASE4.md). Decision: [ADR 0004](../../adr/0004-format-neutral-engine.md). Requirements:
NFR-14, NFR-15.

## Goal

Make the core accept a second format without changing anything for Markdown. This is a refactoring: no user-visible
change, no AsciiDoc code, no new dependency.

## Scope

### API (`pl.mdreview.api`)

- `enum class DocumentFormat { MARKDOWN, ASCIIDOC }`.
- `RenderRequest.format: DocumentFormat = DocumentFormat.MARKDOWN`, after the existing parameters, so positional
  callers compile unchanged.
- `MarkdownDiffRenderer` KDoc: "Compares two Markdown or AsciiDoc sources". No rename.
- A request with `format = ASCIIDOC` and no AsciiDoc front end available returns a `RenderedDiff` from the fallback
  path (raw text, paragraph diff) rather than throwing; P4.6 keeps the viewers from asking for it.

### Engine (`pl.mdreview.engine`)

- `interface BlockSource { fun extract(text: String, options: DiffOptions): List<Block> }`.
- `BlockExtractor` becomes `MarkdownBlockSource` (object), with its current behavior. Static helpers other classes
  use (`HARD_BREAKS_KEY`, `FRONT_MATTER_FENCE_KEY`, `atoms`) stay reachable under the same names.
- `MarkdownDiffEngine` becomes `DiffEngine(options, source: BlockSource = MarkdownBlockSource)`; `diff(left, right)`
  calls `source.extract`, `diff(List<Block>, List<Block>)` is unchanged.
- `Block.node` and `Block.renderNodes` are replaced by `Block.content: BlockContent`:
  ```kotlin
  sealed interface BlockContent {
      data class Commonmark(val nodes: List<Node>) : BlockContent
      data class Html(val parts: List<HtmlFragment.Part>) : BlockContent
      data object Raw : BlockContent
  }
  ```
  Markdown blocks get `Commonmark` (what `renderNodes` held), HTML blocks get `Html`, code lines and front matter
  `Raw`. A `Block.nodes` convenience returns the commonmark nodes or an empty list, so code that reads them changes
  little.
- `BlockContext.containers: List<Container> = emptyList()`, with
  `data class Container(val kind: String, val type: String? = null, val title: String? = null)`. Markdown leaves it
  empty; `quoteDepth` and `alert` keep their meaning.
- `DiffOptions` is unchanged.

### Render (`pl.mdreview.render`)

- `DiffHtmlRenderer.renderBlock` dispatches on `Block.content`; the `Html` branch is today's HTML-block path
  (`markedHtml(parts, marks)`), generalized so it is not tied to `BlockKind.HTML`.
- `LinkChanges` gets an HTML variant: from `BlockContent.Html` parts, collect `<a href>` and `<img src>` with their
  text (alt text for images), pair them by text and occurrence, and return the same `Result` the commonmark variant
  does. Markdown HTML blocks may start using it; their fixtures must not change.
- `CoreMarkdownDiffRenderer` picks the `BlockSource` by `request.format` from a registry
  (`MARKDOWN → MarkdownBlockSource`, `ASCIIDOC → ` whatever P4.3 registers, absent until then).
- `EditRegions` reads kinds and lines only; no change expected beyond the renames.

### Docs

- ENGINE_CONTRACT.md: the `format` input, and a note that the rest of the contract is format-independent.

## Out of scope

AsciiDoc parsing, new block kinds, UI changes.

## Tests

- Every existing unit test, integration test and fixture passes with **no change to expected output**. Test code may
  change only for the renames.
- New: `RenderRequest` without `format` renders as before (a test that compares `bodyHtml` for a few fixtures with and
  without an explicit `MARKDOWN`).
- New: `LinkChanges` HTML variant on fixture `29-html-blocks` and a unit test with a changed `href` behind equal text.
- `RenderBenchmarkTest`: within 5% of the 1.3.0 numbers on the same CI runner (median of three runs).

## Done when

- The checks above are green in CI, `verifyPlugin` included.
- `DiffEngine` and `EditRegions` import nothing from `org.commonmark`; the classes that still do (the Markdown front
  end and its extensions, and the commonmark branch of the renderer) are listed in the PR.
