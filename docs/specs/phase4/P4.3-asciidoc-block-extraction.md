# P4.3 AsciiDoc block extraction

Plan: [PHASE4.md](../../PHASE4.md). Decisions: [ADR 0002](../../adr/0002-asciidoc-parser.md),
[ADR 0005](../../adr/0005-asciidoc-block-model.md). Requirements: FR-17, FR-18 (keys), FR-19 (contexts), FR-23,
FR-24, NFR-13, NFR-15. Depends on P4.1 (source map findings) and P4.2 (`BlockSource`, `BlockContent`).

## Goal

Turn an AsciiDoc text into the list of `Block`s the shared diff engine compares, with correct kinds, keys, plain
text, contexts and line ranges.

## Scope

### Package and wiring

- `pl.mdreview.engine.asciidoc`, platform-free, compiled against AsciidoctorJ `compileOnly`.
- `interface AsciidoctorProvider { fun asciidoctor(): org.asciidoctor.Asciidoctor }`, implemented in the IDE layer
  (P4.6) and in tests with `Asciidoctor.Factory.create()`.
- `class AsciiDocBlockSource(provider: AsciidoctorProvider) : BlockSource`, registered for `DocumentFormat.ASCIIDOC`
  in `CoreMarkdownDiffRenderer`'s registry when a provider exists.

### Parsing

- `load(text, Options.builder().safe(SafeMode.SECURE).sourcemap(true).option("parse_header_only", false)
  .attributes(Attributes.builder().attribute("skip-front-matter", true)...).build())`.
- No `base_dir`, no `to_file`, no `catalog_assets` beyond what block walking needs. Calls serialized behind a lock if
  P4.1 found `load` not thread-safe.
- Any exception from Asciidoctor (a document that Asciidoctor itself cannot process is rare, but extensions or JRuby
  errors are possible) is caught: the side is extracted as raw paragraphs (one block per blank-line-separated run),
  and the HTML generator adds a notice row "AsciiDoc could not be parsed: <message>".

### Walking the tree

Per the table in ADR 0005, depth-first in document order:

- Containers (`example`, `sidebar`, `quote`, `verse`, `open`, admonition blocks) push a `Container` onto
  `BlockContext.containers` for their children, with the type (admonition name) and title.
- Leaves produce one block each: kind, `level`, `language` (from `source` style's `language` attribute), and
  `content = BlockContent.Html(HtmlFragment.parse(converted, allowRemoteImages))` where `converted` is
  `getContent()` (paragraphs), `getText()` (list items, cells), `getTitle()` (sections, block titles).
- Listing and literal blocks produce a `CODE_FENCE` (key: style and language) and one `CODE_LINE` per source line
  (`getLines()` / `getSource()`), `BlockContent.Raw`, like Markdown fences. Callout markers (`<1>`) stay part of the
  line text.
- Tables produce one `TABLE_ROW` per row (header rows first, with a header flag in the key), whose content is the
  cells' converted HTML joined with a cell separator part the renderer turns into `<td>`s, and whose `plainText` is
  the cells' texts joined with ` | `, as Markdown table rows are.
- Lists set `listDepth`, `ordered`, `number` (from `getMarker()` / position) and checklist state (the `checkbox` and
  `checked` attributes) on each item; blocks attached through `+` are walked as children of the item with
  `listDepth + 1`.
- Description lists produce a `DESCRIPTION_TERM` per term and a `LIST_ITEM` for the description text, with its
  attached blocks as children.
- Block images produce `IMAGE` with target and alt text; the key holds both.
- Passthrough blocks produce `HTML` blocks through the existing HTML-block path (sanitized, compared by visible
  text).

### Line scanner

`AsciiDocLines`, a pass over the source lines that runs before the walk:

- finds the header (title, author, revision, attribute entries up to the first blank line) and emits `HEADING` and
  `ATTRIBUTE` blocks for it;
- finds body attribute entries, `//` comments, `////` comment blocks, `include::` lines and preprocessor directives
  (`ifdef`, `ifndef`, `ifeval`, `endif`), outside delimited listing, literal and passthrough blocks, and emits
  `ATTRIBUTE`, `HTML_COMMENT` and `INCLUDE` blocks for them;
- records every delimiter line (`====`, `****`, `____`, `--`, `----`, `....`, `++++`, `|===`) with its matching
  close, for end lines and for edit regions (P4.5);
- gives each tree block its end line: the line before the next block's start or the enclosing close delimiter,
  minus trailing blank lines; attribute lines and anchors directly above a block (`[source,java]`, `[[id]]`,
  `.Title` when not its own block) are recorded as the block's `prefixLines` for P4.5;
- fills in start lines for the nodes P4.1 found without a source location.

The scanner's blocks and the tree's blocks are merged by start line into one list in document order.

### Keys and plain text

- `plainText`: concatenated `TextRun`s of `content` (for `Html`), the line text (for `CODE_LINE`), the entry as
  written (for `ATTRIBUTE`, `INCLUDE`), the comment text (for `HTML_COMMENT`).
- `key`: `"<KIND>:<context>:<normalized source>\u0000<plainText>"`, where context is the pairing context (list depth,
  ordered, checklist state, container kinds and types, table header flag) and the source is the block's own lines
  with trailing whitespace removed. `ignoreWhitespace` is applied by the engine as for Markdown.

### Fixtures

AsciiDoc fixtures live next to the Markdown ones as `<case>/old.adoc`, `new.adoc`, `EXPECTED.md`, numbered from
`50-`; `FixturesTest` picks the format by extension. At least:

| Case | What it checks |
|---|---|
| 50-adoc-paragraph-edit | paragraphs, word diff, inline formatting change only |
| 51-adoc-sections | section text and level changes, discrete headings, document title |
| 52-adoc-lists | nested, ordered, checklist and description lists, list continuations |
| 53-adoc-tables | changed, added and removed rows, header row, `a\|` cell |
| 54-adoc-listing | source blocks: language change, line changes, callouts |
| 55-adoc-admonitions | admonition paragraph and block, type change |
| 56-adoc-containers | example, sidebar, quote, open blocks, nested; content change inside |
| 57-adoc-block-titles | added, removed and changed `.Title` |
| 58-adoc-attributes | header and body attribute entries; a changed value changes a referencing paragraph |
| 59-adoc-comments | line and block comments added and edited; unchanged hidden |
| 60-adoc-includes | `include::` added, removed, target changed; not resolved |
| 61-adoc-links-images | link text vs target, `xref:`, `<<id>>`, inline and block images |
| 62-adoc-conditionals | `ifdef` around a paragraph, condition changed |
| 63-adoc-moved | a moved section |
| 64-adoc-large | ~500 sections, for the benchmark |

## Out of scope

HTML output (P4.4), edit regions (P4.5), the IDE (P4.6), diagrams and formulas (P4.7).

## Tests

- `AsciiDocBlockSourceTest`: per ADR 0005 row, a minimal document and the expected `(kind, lines, plainText,
  context)` list.
- `AsciiDocLinesTest`: delimiter matching (nested, same delimiter length rules), header detection, comments inside
  listing blocks not treated as comments.
- The fixtures above through `FixturesTest` (block statuses and word diffs from `EXPECTED.md`).
- A property test: for every fixture side, the blocks' line ranges are in order, do not overlap, and every non-blank
  source line outside delimiters and prefix lines belongs to exactly one block.
- `RenderBenchmarkTest` gets AsciiDoc entries at 1,000 and 10,000 lines (reporting, not gating, as NFR-2).

## Done when

- All AsciiDoc fixtures pass, and the property test holds for all of them.
- The steady-state benchmark meets NFR-12.
