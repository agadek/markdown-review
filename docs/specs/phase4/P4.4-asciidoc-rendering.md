# P4.4 AsciiDoc HTML rendering and change marks

Plan: [PHASE4.md](../../PHASE4.md). Decision: [ADR 0006](../../adr/0006-asciidoc-rendering-reuse.md). Requirements:
FR-17, FR-18, FR-19, NFR-5, NFR-8, NFR-13. Depends on P4.3.

## Goal

Render an AsciiDoc diff in the side-by-side and merged views with the same look, DOM contract and change marks as a
Markdown diff.

## Scope

### Block markup

`DiffHtmlRenderer` writes, per kind, inside the usual `.mdr-side` / merged item with `data-side`, `data-line`,
`data-idx` and `blk-*`:

| Kind | Markup |
|---|---|
| `HEADING` | `h1`–`h6` with the converted title |
| `PARAGRAPH` | `p` |
| `LIST_ITEM` | `ul`/`ol` > `li` at its depth, as for Markdown; checklist items with the existing checkbox markup |
| `DESCRIPTION_TERM` | `dl.mdr-dlist > dt`; the description item is `dl.mdr-dlist > dd` |
| `TABLE_ROW` | `table > tr > th/td`, header row as `th`; column widths not reproduced |
| `CODE_FENCE`, `CODE_LINE` | as Markdown fences (`pre`, language label) |
| `ALERT` | the existing alert markup and class for the type |
| `BLOCK_TITLE` | `div.mdr-block-title` |
| `IMAGE` | `figure > img` (and `figcaption` from its title), through the image path of Markdown images, so base URI resolution, `mdr-img-changed` and the remote image rule apply |
| `ATTRIBUTE` | `div.mdr-attribute` with name and value in monospace, like a front matter line |
| `INCLUDE` | `div.mdr-include` with a link to the target, resolved against the side's base URI |
| `HTML_COMMENT` | as Markdown comments: hidden unless changed |
| `THEMATIC_BREAK` | `hr` (page break: `hr.mdr-page-break`) |

### Containers

Consecutive rows that share a `Container` prefix are drawn inside a frame, the way quoted rows are:
`div.mdr-container.mdr-container-<kind>` on each side of each row, nested by depth, with the container's title as a
`mdr-block-title` on its first row and the admonition icon for admonition containers. In the side-by-side view a
container that exists on only one side frames that side only; the placeholder on the other side has no frame.

### Inline content

- Inline HTML from Asciidoctor is already sanitized parts (P4.3). The allowlist adds `mark` and keeps `class` only for
  the Asciidoctor inline classes styled below; it adds nothing that can run script (NFR-8). This change is reviewed
  against fixture `31-html-sanitizer`, which must not change, plus a new AsciiDoc sanitizer case (passthroughs with
  `<script>`, `on*`, `javascript:` links).
- Styles: `kbd` (existing), `span.menuseq` and `b.menuref` as menu paths, `mark` from `--md-modified-bg`, footnote
  references and the footnotes list as Markdown footnotes.
- Word marks: `markedHtml(parts, marks)` from P4.2. In the merged view removed words are inserted at their offsets as
  for HTML blocks.

### Change notes and marks

Reusing the existing notes (`mdr-meta-changed`, `data-change-note`):

- section level: `h2 → h3`;
- admonition type: the existing alert-type note;
- source language: `java → kotlin` on the fence row;
- checklist state: the existing checked/unchecked note;
- block title: a changed `BLOCK_TITLE` row is an ordinary modified block with a word diff;
- link and image targets, `xref:` and `<<id>>` targets: the HTML variant of `LinkChanges` (P4.2), so equal text with
  a changed target gets `mdr-link-changed` and the `Previous URL` / `New URL` title;
- an inline-only markup change (for example `*word*` to `_word_`): the block is modified with no word change, and
  gets the note `formatting changed` (new label in `Labels`, also used by Markdown if it ever needs it).

### Styles

- `diff.css`: `mdr-container-*`, `mdr-block-title`, `mdr-dlist`, `mdr-callout`, `mdr-include`, `mdr-attribute`,
  `mdr-page-break`, `menuseq`, `mark`. Only the existing CSS variables, no `prefers-color-scheme` (NFR-5).
- `CLASSES.md` and `demo.html`: the new classes, with an AsciiDoc section in the demo.

## Out of scope

Diagrams and formulas (P4.7), revert and apply (P4.5), Asciidoctor's own stylesheet and block HTML (ADR 0006).

## Tests

- `DiffHtmlRendererTest`: one test per kind and per container in both modes, asserting the DOM contract attributes
  and classes.
- `CoreMarkdownDiffRendererTest`: AsciiDoc fixtures render without exceptions in both modes, and every changed
  block has a visible mark (a `del`/`ins`, a `mdr-*-changed` class or a change note), so no change exists only in
  the source.
- HTML snapshot of `56-adoc-containers` and `61-adoc-links-images` in both modes.
- Manual: `demo.html` in light and dark, and the fixtures in `runIde` once P4.6 lands, compared against the same
  documents rendered by the AsciiDoc plugin's preview for structure (not styling).

## Done when

- Every AsciiDoc fixture renders in both modes, light and dark, with no unstyled Asciidoctor markup.
- Fixture `31-html-sanitizer` is unchanged and the AsciiDoc sanitizer case passes.
