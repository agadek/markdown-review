# P4.5 Edit regions, revert, apply, block editing and moves

Plan: [PHASE4.md](../../PHASE4.md). Decisions: [ADR 0004](../../adr/0004-format-neutral-engine.md),
[ADR 0005](../../adr/0005-asciidoc-block-model.md). Requirements: FR-20, NFR-7. Depends on P4.3.

## Goal

Give every changed AsciiDoc block an `EditRegion` that revert and apply can exchange without breaking the
document's structure, so the IDE's existing per-block buttons, block editing and move handling work for AsciiDoc.

## Scope

### Edit regions

`EditRegions` already works on kinds and lines. AsciiDoc adds these rules, expressed through a small per-format
`RegionRules` interface so the Markdown rules stay where they are:

- **Prefix lines**: a block's attribute line, anchor and block title above it (`prefixLines` from P4.3) belong to its
  region, so reverting a source block also reverts its `[source,java]` line. A `BLOCK_TITLE` that is its own block
  exchanges only its line.
- **Delimited code blocks** (`----`, `....`, `++++`, stem and Mermaid blocks) added or removed as a whole are one region
  for all their blocks, including both delimiters, like a Markdown fence. A modified code line exchanges only its
  line.
- **Containers** added or removed as a whole are one region from the opening delimiter (with its prefix lines) to the
  closing one. A change inside an existing container exchanges only the inner block's lines, so the delimiters are
  never touched.
- **Tables**: a modified row exchanges its lines; a table added or removed as a whole is one region from `|===` to
  `|===`; the header row of a table whose `[options="header"]` changed exchanges the attribute line too.
- **Lists**: a list item with continuations (`+` and the attached blocks) is one region when added or removed; a
  modified item's text exchanges only its own lines.
- **Header**: header lines exchange one line at a time; an added or removed header (title plus attributes) is one
  region up to the blank line that ends it.
- **Comments and includes**: one line, or the whole `////` block.
- A region that would leave a delimiter unbalanced is not offered: `edit = null`, as for Markdown changes no line edit
  can undo. The test below proves none of the fixtures hits this.

### Block editing

No change in the IDE: the editor opens on `BlockInfo.left` / `right` lines, which for AsciiDoc include no prefix
lines. Saving replaces those lines. The textarea's label says "AsciiDoc" instead of "Markdown" (new message key).

### Moves

The engine's move linking runs unchanged. `UNMOVABLE_KINDS` gains `ATTRIBUTE`, `INCLUDE` and `BLOCK_TITLE` (too easy
to match), and keeps code lines, fences, comments and thematic breaks. A moved block's edit regions include its
prefix lines, so a moved titled listing moves with its title.

## Out of scope

The IDE side of edits (unchanged), three-way merge.

## Tests

- `EditRegionsTest`: one AsciiDoc case per rule above.
- Round trip on every AsciiDoc fixture, as for Markdown: apply every changed block's region left to right in one
  pass, and the result equals `new.adoc`; revert every one right to left, and the result equals `old.adoc`. Each
  result must still parse with Asciidoctor to the same block tree as the target side.
- Moves: `63-adoc-moved` reverts both ends in one command.
- `BlockActionsTest` (integration): revert and apply on an AsciiDoc document in `runIde`-style tests, one Undo each.

## Done when

- The round trip holds for every AsciiDoc fixture, and no changed block in them has `edit = null`.
