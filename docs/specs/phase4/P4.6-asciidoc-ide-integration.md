# P4.6 IDE integration

Plan: [PHASE4.md](../../PHASE4.md). Decisions: [ADR 0003](../../adr/0003-asciidoctorj-from-asciidoc-plugin.md),
[ADR 0007](../../adr/0007-asciidoc-ide-integration.md). Requirements: FR-16, FR-20, FR-21, NFR-6, NFR-11, NFR-12.
Depends on P4.1 and P4.4; edit actions need P4.5.

## Goal

Make AsciiDoc diffs open rendered everywhere Markdown diffs do, while the AsciiDoc plugin is enabled, and stay out
of the way while it is not.

## Scope

### Optional descriptor and provider

- `plugin.xml`: `<depends optional="true" config-file="markdown-review-withAsciiDoc.xml">org.asciidoctor.intellij.asciidoc</depends>`.
- New extension point `pl.mdreview.asciidoctorProvider` (interface `AsciidoctorProvider` from P4.3, dynamic).
- `markdown-review-withAsciiDoc.xml` registers:
  - `pl.mdreview.ide.asciidoc.PluginAsciidoctorProvider`: an application service that creates the `Asciidoctor`
    instance once, on a pooled thread, with the AsciiDoc plugin's class loader as context class loader (the setup P4.1
    recorded), and closes it in `dispose()`;
  - `pl.mdreview.ide.asciidoc.AsciiDocFileTypeRecognizer` for the AsciiDoc plugin's file type.
- `RendererProvider` registers `AsciiDocBlockSource` with the core when the extension point has an implementation,
  and unregisters it when the extension is removed (dynamic plugin unload).

### File recognition

- `MarkdownFiles` becomes `ReviewFiles` with `formatOf(file: VirtualFile)`, `formatOf(path: FilePath)` and
  `formatOf(fileType: FileType)`, returning `DocumentFormat?`. Markdown: as today. AsciiDoc: extensions `adoc`,
  `asciidoc`, or the recognizer's file type (which covers `.asc` and custom patterns).
- `formatOf` returns `ASCIIDOC` only when a provider is registered, so every caller gets "not supported" while the
  AsciiDoc plugin is missing, without checking it itself.

### Viewers

- `RenderedMarkdownDiffTool.accepts`: both existing sides have the same non-null format. A pair of different formats
  is not accepted (text viewer).
- `RenderedDiffViewer` passes `format` in `RenderRequest`.
- First AsciiDoc render in a session: when the provider's instance is not ready, the panel shows
  "Preparing AsciiDoc renderer..." (same styling as the large-file notice, no button) and renders when the instance is
  ready. A failure to create it shows "AsciiDoc rendering is not available: <message>" with an **Open Text Viewer**
  button, reports through the error reporter once per session, and later AsciiDoc requests go to the text viewer.
- A `LinkageError` or JRuby exception during a render is caught in the viewer, logged once, and shown as the same
  notice.
- Tool names: `tool.side.by.side=Rendered (side by side)`, `tool.merged=Rendered (merged)`. Class names unchanged
  (ADR 0001).

### Actions

- **Compare Markdown Files...** (`MarkdownReview.CompareFiles`, ID unchanged) becomes **Compare Rendered Files...**,
  enabled for one or two files of one supported format; the chooser filters for that format.
- **Show Rendered Diff** and **Export Rendered Diff | HTML... / PDF...** accept changes whose before or after path is
  AsciiDoc (and supported); multi-file export may mix formats, each file rendered with its own format.
- Descriptions in `MarkdownReviewBundle.properties` say "Markdown or AsciiDoc".

### Settings

- Settings | Tools | Markdown Review: under the existing options, a line "AsciiDoc: available" or "AsciiDoc diffs need
  the AsciiDoc plugin" with a link that opens the plugin's Marketplace page in the Plugins settings.
- No new options. Existing ones apply to both formats.

### Build

- `build.gradle.kts`: `plugin("org.asciidoctor.intellij.asciidoc", "<version for 251>")` in `intellijPlatform`
  dependencies, AsciidoctorJ `compileOnly` and `testImplementation` at the version P4.1 recorded.
- `pluginVerification`: unchanged IDE list; the AsciiDoc plugin is resolved for each.
- Check that `buildPlugin` bundles no `org.asciidoctor` or `org.jruby` classes (a Gradle check that fails the build if
  the zip contains them), for NFR-14.

## Out of scope

A rename of the plugin or settings page, separate default viewers per format.

## Tests

- `MarkdownDiffToolsTest`: `canShow` for `.adoc` with and without a provider, for mixed `.md` / `.adoc` pairs, and for
  an `.asc` file with and without the AsciiDoc file type.
- `CompareMarkdownFilesActionTest`, `ShowRenderedDiffActionTest`, `ExportRenderedDiffActionTest`: AsciiDoc cases, and a
  mixed-format multi-file export.
- `RenderedDiffViewerTest`: the "Preparing" notice while the provider is not ready (with a test provider that blocks),
  and the failure notice when it throws.
- Manual in `runIde`, with the AsciiDoc plugin: Commit window, Git log, file history, **Compare Rendered Files...**,
  export, revert and apply, block editing, block menu; then disable the AsciiDoc plugin without restart and check the
  same `.adoc` diff falls back to the text viewer with no errors, and that Markdown diffs are unaffected.
- Manual: the first-render time against NFR-12.

## Done when

- The tests pass in CI and the manual checklist is filled in for IC 2025.1.3 and the newest IDE in the verification
  list.
- The plugin zip contains no AsciidoctorJ or JRuby classes, and its size grows by less than 1 MB.
