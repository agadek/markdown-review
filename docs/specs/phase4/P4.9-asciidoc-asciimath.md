# P4.9 AsciiMath in AsciiDoc

Plan: [PHASE4.md](../../PHASE4.md). Decision: [ADR 0008](../../adr/0008-asciimath-to-latex.md). Requirement:
FR-25. Depends on P4.7. Ships in 1.4.0, before P4.8's release.

## Goal

Draw AsciiMath formulas, the default math notation of Asciidoctor, with the bundled KaTeX, so that `stem:[...]`,
`asciimath:[...]` and `[stem]` / `[asciimath]` blocks look and diff like `latexmath` ones.

## Scope

### Converter

- `AsciiMathToTex.convert(source: String): String?` in `pl.mdreview.engine.asciidoc`, platform-free, no I/O.
- Grammar and symbols from the AsciiMath reference: constants and Greek letters, operation and relation symbols,
  logical symbols, arrows, miscellaneous symbols, standard functions (`sin`, `log`, `lim`, ...), accents (`hat`,
  `bar`, `vec`, `dot`, `ddot`, `ul`, `obrace`, `ubrace`), font commands (`bb`, `bbb`, `cc`, `tt`, `fr`, `sf`),
  `sqrt`, `root`, `frac`, `stackrel`, `overset`, `underset`, `color`, `cancel`, `abs`, `floor`, `ceil`, `norm`.
- Simple expressions with `/` for fractions, `_` and `^` for sub- and superscripts (including `sum_(i=1)^n`),
  brackets `()`, `[]`, `{}`, `(: :)`, `<< >>` and the invisible `{: :}`, and matrices and vectors written as
  bracketed rows (`[[a,b],[c,d]]`, `((1),(2))`).
- `text(...)`, `"quoted text"` and `mbox(...)` as `\text{...}`.
- Unknown words stay as letters, as in the reference; only input that cannot be parsed (unbalanced brackets, a
  dangling `/`, `_` or `^`) returns `null`.

### Front end and rendering

- Inline `asciimath:[...]` and, when `stem` is `asciimath` or unset, `stem:[...]` become
  `span.mdr-math.mdr-math-inline` with the converted LaTeX and `data-source` holding the AsciiMath; they are atoms of
  `plainText` keyed by the AsciiMath source, as P4.7 does for LaTeX.
- `[asciimath]` blocks and AsciiMath `[stem]` blocks become `MATH` blocks drawn in display mode, with their AsciiMath
  lines for the source diff.
- `mdrDrawMath` restores `data-source` when KaTeX fails, so the failure shows the formula as written. LaTeX formulas,
  which have no `data-source`, keep today's behavior.
- A formula the converter rejects stays source with `mdr-math-failed` and the note "AsciiMath formula could not be
  converted".
- `Render math` off: unchanged, all formulas stay source.

## Out of scope

AsciiMath in Markdown files, MathML output, and AsciiMath extensions that need MathJax-only commands.

## Tests

- `AsciiMathToTexTest`: every example on the AsciiMath reference page, plus the formulas in fixture `66-adoc-math`,
  each converted and then rendered by KaTeX without an error (KaTeX runs in the existing page test harness).
- Rejected input: unbalanced brackets, a dangling operator, an empty formula.
- Fixture `66-adoc-math` updated: its AsciiMath formulas are now drawn; a changed AsciiMath formula is one atom; a
  formula changed only in spelling (`a/b` to `frac(a)(b)`) is still marked as changed.
- New fixture `67-adoc-asciimath`: `:stem:` without a value, inline and block `stem`, matrices, a rejected formula.
- `HtmlPageTest`: KaTeX is inlined for a page whose only formulas are AsciiMath.
- Markdown fixtures, including `40-math`, are unchanged.

## Done when

- Both fixtures render in both modes, light and dark, with AsciiMath drawn, and their exports include the drawings.
- The plugin zip stays within NFR-14, and no new third-party library is bundled.
- SPECIFICATION.md, README, the docs site and the CHANGELOG no longer say AsciiMath is not supported.
